## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
After upgrading Spring Boot from 4.0.3 to 4.1.0 (and transitively Spring Data JDBC/Relational), list endpoints generated by `GetListServiceWriter` can bind string filter values incorrectly through the Query-by-Example path. In the kafka example this shows up as `findChannelSummaries` returning an empty page even though `channel_summary` rows are persisted.

The generated service currently uses:
- `Example.of(...)`
- `ExampleMatcher.matchingAll()`
- `.withMatcher("name", ExampleMatcher.GenericPropertyMatchers.ignoreCase().contains())`

Observed runtime behavior in failing test/logging indicates the SQL `LIKE` bind value becomes a `ValueFunction` lambda object rather than a string pattern, so the query never matches.
<!-- SECTION:DESCRIPTION:END -->
